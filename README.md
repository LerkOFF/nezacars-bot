# nezacars-bot

Клон Telegram-бота `@chinacars_market_bot` (каталог автомобилей из Китая). Наш бот: `@nezacars_bot`.

Бот не хранит состояние и работает только через deep-link `/start <payload>`, как оригинал. Ссылки в кнопках и в списках ведут обратно в этот же чат.

| payload | ответ |
| --- | --- |
| пусто, `catalog` | главное меню: 5 категорий, «БРЕНДЫ», 20 марок по две в ряд, «Как заказать» |
| `cat_do160`, `cat_hybrid`, `cat_minivan`, `cat_electric`, `cat_over160` | список авто категории |
| `brand_<ключ>` (`brand_Audi`, `brand_LiAuto`, `brand_LynkCo`, `brand_MercedesBenz` ...) | список авто марки; если пусто, «Сейчас автомобилей X нет в каталоге» и ссылка «Отправить запрос» |
| `howto` | «Как заказать» |
| любое другое (`Zeekr`) | «Спасибо за обращение», запрос уходит админам; если у человека нет `@username`, через `followup_delay_sec` (по умолчанию 20 минут) бот сам пришлёт «Не можем написать вам с личного аккаунта менеджера…» с кнопкой «💬 Написать <менеджер>» (так делает оригинал) |

Каждый список заканчивается кнопкой «Вернуться в каталог». Длинные списки режутся на несколько сообщений.

## Запуск

```bash
cp .env.example .env   # BOT_TOKEN, ADMIN_CHAT_IDS
python3 bot.py
python3 -m unittest discover -s tests
```

Очередь отложенных сообщений лежит в `state/followups.json` (в git не попадает) и переживает перезапуск. Для проверки задержку можно сократить: `FOLLOWUP_DELAY_SEC=15`.

Только стандартная библиотека Python 3. Токен только в `.env` (в git не попадает). Админ должен один раз нажать Start у бота, иначе уведомления о запросах не дойдут.

## Меню-пост в канале

У оригинала меню лежит постом в канале, а не в боте. Для нашего канала это делает `post_menu.py`:

```bash
python3 post_menu.py @Nezavisimost_Ru --dry-run   # посмотреть, что уйдёт
python3 post_menu.py @Nezavisimost_Ru --pin       # опубликовать и закрепить
```

Бот должен быть админом канала с правом публиковать (и закреплять). Скрипт печатает ссылку на пост, её можно вписать в `back_url` в `data/config.json`.

## Данные

- `data/config.json`: тексты, раскладка меню, менеджеры (`managers`: `[{"name": "Сергей", "name_instr": "Сергеем", "name_dat": "Сергею", "url": "https://t.me/..."}]`, `name_instr` и `name_dat` для падежей в текстах («с менеджером Сергеем», «Написать Сергею»), сейчас пусто; для отложенного сообщения используется первый), тексты `followup_*`, `back_url` (куда ведёт «Вернуться в каталог», пусто = меню бота).
- `data/catalog.json`: `cars` (`id` → `title`, `price` числом или `null` = «Цена по запросу», `url` карточки), `categories` и `brands` (заголовок и упорядоченный список id авто). Файлы перечитываются на лету, перезапуск не нужен.

Сейчас в каталоге то, что отдавал оригинал на 2026-10-22 (41 авто, ссылки карточек на `t.me/chinacarsmarkt/*`). Для своего каталога заменить `cars` и списки в `categories`/`brands`; марка без авто сама покажет «нет в каталоге».

## Чем отличается от оригинала

- Пустой `/start` у оригинала молчит, у нас показывает меню.
- «БРЕНДЫ», «Как заказать» и «Вернуться в каталог» у оригинала ведут на посты канала `@chinacarsmarkt`, у нас на меню и текст внутри бота.
- Цены без пробелов («9700000 ₽») и пустая «машина» у Tesla в оригинале выглядели как ошибки данных, у нас цены форматируются единообразно, пустая марка показывает «нет в каталоге».
- Менеджеры оригинала (Сергей, Вячеслав) не скопированы, кнопки менеджеров появятся, когда они заданы в `config.json`.
- Текст пустой категории в оригинале не наблюдался (у всех пяти категорий есть авто), текст `empty_category_text` придуман.
